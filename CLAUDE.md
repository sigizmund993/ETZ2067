# ETZ — полигон ВсОШ Робототехника 2026-27 (проектный тур)

Проект: 3D-модель полигона по краткому ЕТЗ (техзадание) для проектного тура
ВсОШ по робототехнике, сезон 2026-27. Модель строится в FreeCAD.

## Файлы проекта

- [etz_kratko_26_27_копия.pdf](etz_kratko_26_27_копия.pdf) — исходное ТЗ (23 стр.), источник всех размеров/требований.
- [ETZ_poligon.FCMacro](ETZ_poligon.FCMacro) — **основной скрипт-генератор модели** (Python). Пересобирает документ `ETZ_Poligon` с нуля при каждом запуске (`App.closeDocument` + `App.newDocument`). Правки вносятся сюда, а не руками в .FCStd.
- [ETZ_Poligon.FCStd](ETZ_Poligon.FCStd) — сохранённый документ FreeCAD (результат работы макроса), открыт прямо сейчас в GUI.
- `freecad-mcp.mcpb` — упакованное расширение для Claude Desktop (см. ниже). Выдано пользователю, в репозитории не обязательно хранить дальше.
- `freecad-mcpb/manifest.json` — исходник манифеста, из которого собран `.mcpb` (на случай пересборки, напр. при добавлении auth-токена).

## Что строит макет (ETZ_poligon.FCMacro)

Глобальная СК: начало — левый нижний угол полигона 600×500 мм, X вправо, Y вверх,
Z вверх от поверхности. Координаты поля ЕТЗ (п. 2.2) переводятся через
`field_to_global()`, начало поля O = центр метки ArUco id 27.

Группы объектов в документе:
- **Полигон** (5 объектов) — основание, зона 1 (350×500), зона 2 (верх/низ, 250×80 каждая), область операционного поля (250×330).
- **Операционное поле** (13 объектов) — лист А4-шаблон, чёрные ограничительные полосы, красная сетка 9×6 клеток по 28 мм, чёрные круги Ø6 и зелёные окружности Ø24,5 в центрах клеток + столбец отбоя, три метки ArUco (DICT_4X4_50, id 27/28/29) с чёрными/белыми частями, оси поля.
- **Шашки** (по 2 объекта на штуку: корпус + шайба) — расставляются по списку `CHECKERS` в начале макроса: `(клетка, цвет[, высота_стопки])`. Клетка — `"Б3"` (буква А..Е = ряд, цифра = столбец) или `"Отбой1".."Отбой5"`. Шашка: Ø26×5, крышка 0,8 мм, стенка 0,9 мм; внутри шайба М8 (ГОСТ 6958-78) Ø24×2 с отверстием Ø8,4, прилегает к крышке.

Чтобы переставить/перекрасить шашки или изменить расстановку — правь только список
`CHECKERS` и/или словарь `COLORS` в начале файла, затем пересобери документ (см. ниже).

## Как пересобрать модель

Через MCP (`execute_code` на документе, либо headless):
```python
exec(compile(open('/home/semen/ETZ/ETZ_poligon.FCMacro', encoding='utf-8').read(),
             '/home/semen/ETZ/ETZ_poligon.FCMacro', 'exec'), {'__name__': '__main__'})
```
Макрос сам закрывает старый документ `ETZ_Poligon` и строит заново, затем делает
`viewIsometric()` + `ViewFit`. После пересборки стоит сохранить:
```python
App.getDocument('ETZ_Poligon').save()
```

## MCP-подключение к FreeCAD (как это работает)

Установлен официальный **freecad-mcp** (neka-nat, https://github.com/neka-nat/freecad-mcp), версия **0.1.25**. Два независимых компонента:

1. **Аддон внутри FreeCAD** (workbench "MCP Addon") — поднимает XML-RPC сервер
   на `127.0.0.1:9875`. Установлен в
   `~/.var/app/org.freecad.FreeCAD/data/FreeCAD/v1-1/Mod/FreeCADMCP/`
   (FreeCAD запущен как **flatpak**, `org.freecad.FreeCAD`, 1.1.3 — это важно,
   пути Mod/настроек у flatpak свои, см. ниже).
   Автостарт сервера включён через файл настроек аддона:
   `~/.var/app/org.freecad.FreeCAD/data/FreeCAD/v1-1/freecad_mcp_settings.json`
   (`"auto_start_rpc": true`) — сервер поднимается сам при каждом запуске
   FreeCAD, кнопку жать не нужно.
2. **MCP-сервер** `freecad-mcp` (pip-пакет, `pip install --user freecad-mcp`,
   бинарник `/home/semen/.local/bin/freecad-mcp`) — это именно то, с чем
   говорит Claude по протоколу MCP (stdio). Внутри он сам ходит по XML-RPC к
   порту 9875. Нужен Python ≥3.12 (системный `python3` на машине — 3.12.3,
   подходит; Python самого FreeCAD — 3.13, это другое, отдельное окружение).

Эти два компонента общаются только друг с другом через localhost:9875 — FreeCAD
должен быть запущен (с аддоном) **до** того, как Claude дёргает инструменты.

### Как подключено к Claude

Собран и установлен `.mcpb`-бандл (`freecad-mcp.mcpb`, через официальный CLI
`@anthropic-ai/mcpb`, `npx @anthropic-ai/mcpb pack`). В `manifest.json` —
`"server": {"type": "binary", "mcp_config": {"command": "/home/semen/.local/bin/freecad-mcp", "args": ["--only-text-feedback"]}}`.
Код сервера НЕ забандлен внутрь `.mcpb` — манифест просто указывает на уже
установленный путь, это рабочий вариант (`type: "binary"` не обязан быть
внутри архива).

Поставлено пользователем через **Settings → Extensions → install file** в
Claude Desktop (это НЕ обычный open-source Claude Desktop — внутреннее
приложение c "cowork"/"epitaxy"-движком; отдельного CLI `claude` тут нет,
`claude mcp add` не работает, классический `claude_desktop_config.json` с
ключом `mcpServers` тоже не читается — MCP-серверы живут только как
расширения `.dxt/.mcpb` через Settings → Extensions либо как коннекторы из
реестра через Settings → Connectors).

Подключение проверено end-to-end (см. чейнджлог) — Claude Desktop сам
спавнит процесс `freecad-mcp --only-text-feedback` (родитель —
`/usr/lib/claude-desktop/claude-desktop`), тот коннектится к FreeCAD, видит
документ `ETZ_Poligon`.

**Важный нюанс:** список MCP-инструментов сессии Claude фиксируется при
старте. Если FreeCAD только что переоткрыт/переустановлен аддон — новые
инструменты появятся только в **новом чате**, не в текущем.

## Известные нюансы / грабли на будущее

- Flatpak FreeCAD: **не используй `/tmp`** для файлов, которыми обмениваешься
  с процессом FreeCAD — пиши в `/home/semen/ETZ` или другой путь под `$HOME`.
- `pkill -f FreeCAD` в этом окружении почему-то не проходит через
  sandbox-разрешения Bash-тула (тихо фейлится, даёт `Exit code 1` без вывода).
  Используй `kill -9 <pid>` по явным PID из `ps aux`.
- Цвета `ViewObject.ShapeColor` в современном FreeCAD требуют **однородного**
  типа внутри кортежа — либо все int, либо все float, смешивать нельзя.
- Если меняешь `CHECKERS`/геометрию и видишь похожую ошибку — ищи такие же
  смешанные кортежи по аналогии.
- `freecad-mcp` требует Python ≥3.12 на стороне MCP-сервера — это системный
  `python3`, НЕ питон самого FreeCAD (у FreeCAD 1.1 свой встроенный 3.13,
  отдельный от системного).
- Если переустанавливаешь аддон или обновляешь `freecad-mcp` — версии должны
  совпадать (`get_rpc_status` → `version_check`), иначе будет варнинг о
  рассинхроне; после обновления аддона — перезапусти FreeCAD.

Поставлена официальная [FreeCAD-library](https://github.com/FreeCAD/FreeCAD-library)

**Клон разряженный (sparse), а не полный** — на диске было всего 1,5 ГБ свободно
(99% занято), полная библиотека ~1 ГБ. Сделано так:
```bash

  https://github.com/FreeCAD/FreeCAD-library.git <path>/Mod/parts_library
cd <path>/Mod/parts_library && git sparse-checkout set "Mechanical Parts/Bearings"
```

Итого 20 МБ. Добавить ещё раздел — `git sparse-checkout add "Mechanical Parts/Pulleys"`
(нужна сеть: blob'ы докачиваются по требованию).

Грабли:
- `get_parts_list` фильтрует по расширению **`.FCStd` с учётом регистра**, а в
  библиотеке половина файлов названа `.fcstd` строчными — в списке их не видно,
  но `insert_part_from_library` по явному пути их открывает нормально.
  Пример: `Mechanical Parts/Bearings/608ZZ_Ball_Bearing.fcstd`.

  `Chamfer` — PartDesign-фичи без Body). Для покупной детали параметрика не

- Шейпы в библиотеке не обязаны стоять осью по Z (у 608ZZ ось вдоль **Y**),

  `Shape.Placement` новое значение — исходный поворот теряется; нужно либо
  домножать на старый, либо задавать поворот явно.

## Параметрический привод руки (shkiv_param.FCMacro)

[shkiv_param.FCMacro](shkiv_param.FCMacro) строит ведомый шкив GT2 с седлом
под трубу руки и отдельную прижимную крышку. Все размеры живут в объекте
**VarSet `Privod` (ярлык «Привод»)** в дереве документа `ETZ_Robot` — после
первой сборки макрос не нужен, геометрия меняется правкой переменных в GUI.

Ключевые связи (выражениями, пересчитываются сами):
- `Peredacha` -> `ZubVedom = round(ZubVed * Peredacha)` -> делительный Ø,
  вершины, фланцы, `Occurrences` кругового массива зубьев;
- `Peredacha` + `DlinaRemnya` -> `MezhOs` (решение формулы длины ремня) ->
  `Part002.Placement.Base.y`, то есть весь узел отъезжает от вала мотора;
- `VenecZ` -> `Part002.Placement.Base.z`, венцы ведущего и ведомого совпадают;
- `DiamTruby` -> жёлоб седла, крышка, положение и Ø винтов хомута;
- `OknoChislo`/`OknoUgol` -> окна облегчения. Фаза первого окна считается как
  `180/OknoChislo - OknoUgol/2`, поэтому спица **всегда** приходится ровно под
  седло руки, а не под окно, при любом числе окон.

Крепёж хомута: винт идёт сверху через зенковку в крышке и затягивается в
гайку M3, лежащей в пазу седла (паз открыт на боковую грань, гайка заводится
сбоку). Тянущее усилие держит потолок паза; подошвы под гайкой нет — там,
где седло свисает за фланец, её было бы не на чем печатать.

Ближняя к центру пара винтов (`VintX1`) сверлится **насквозь через весь
шкив** — винт может выходить за гайку, поэтому его длина перестаёт быть
критичной. Дальняя пара (`VintX2`) висит за фланцем, там сверлить нечего,
и её отверстие остаётся глухим на 2 мм ниже гайки. Условие в
`build_pulley()` — флаг `skvoz`. Проверено: сквозное отверстие оставляет
1.93 мм стенки до границы окна облегчения, 7.84 мм до гнезда подшипника.

Сквозных вырезов доступа под гайки в шкиве НЕТ. Пробовались, но
прямоугольный вырез пересекал наклонную границу окна облегчения и оставлял
в окне зуб ~2x1 мм. Шестигранный вырез эту проблему снимал, но доступ
оказался не нужен — убрано.

Геометрия собрана на **примитивах PartDesign** (`AdditiveCylinder/Box`,
`SubtractiveCylinder/Box`), а не на эскизах: у примитива каждый размер — своё
свойство под выражение, и нет зависимости от имён рёбер.

`pulley_100t.FCMacro.superseded` — прежняя непараметрическая версия. Не
запускать: она перестроит то же `Body003` жёстко заданными числами и снесёт
всю цепочку с выражениями.

### Грабли движка выражений FreeCAD

- **Имя свойства не должно совпадать с обозначением единицы.** Свойство с
  именем `C` (кулон) ломает любое выражение, которое на него ссылается, —
  с бесполезным сообщением «Expression can not evaluate to a value».
  Так же опасны `T`, `N`, `F`, `W`, `J`, `A`, `K`, `S`, `V`, `L`.
- **Одно сломанное выражение отравляет весь документ.** После него *любой*
  последующий `setExpression`/`recompute` возвращает ту же обобщённую ошибку,
  даже для заведомо корректных выражений и в другом объекте. Диагностируя,
  сначала удалите свойство с битым выражением, иначе будете чинить исправное.
- `sqrt` не умеет единицы: пишите `sqrt(X / 1mm^2) * 1mm`.
- `max(a; b)` и `max(a, b)` оба работают. Для формулы межосевого расстояния
  `max(..., 0 mm^2)` обязателен: при слишком коротком ремне подкоренное
  выражение уходит в минус, `sqrt` даёт **nan**, и объект молча уезжает в
  неопределённую точку вместо ошибки.
- Python-число нельзя складывать с `Quantity` — «Unit mismatch in plus
  operation». Берите `.Value`.

### Грабли PartDesign/API

- `doc.removeObject(body.Name)` на теле **не удаляет его фичи** — они
  осиротеют. В дереве при этом видно только хвост цепочки (фичи показывают
  свой `BaseFeature` как ребёнка), поэтому чистить надо слоями, пока не
  кончатся. См. `purge_orphans()` в макросе.
- `obj.getGlobalPlacement()` **уже включает** собственный `Placement`
  объекта, а у `Part::Feature` `Shape.Placement` — это он же. Перемножать
  их нельзя: получите двойное смещение и ложные «пересечения» при проверке
  сборки. Правильно:
  `shape.Placement = obj.getGlobalPlacement() * obj.Placement.inverse() * shape.Placement`.

### Скруглений в модели нет — и почему не стоит пробовать снова

`PartDesign::Fillet` по стыку седла и шкива пробовался и **снят**. Если
соберётесь повторить — вот что выяснилось, чтобы не ходить по кругу.

Корень седла стоит над окном облегчения, поэтому линия стыка разорвана:
её куски — короткие диагонали по наклонной границе окна (3.8 мм) вперемешку
с обрезками по 0.2–0.4 мм. На таких рёбрах галтель не встаёт **ни на каком
радиусе** (проверено до 0.25 мм), не встаёт и фаска, и не помогает подача
всей цепочки разом: материала под ребром местами просто нет.

Что при этом ломалось:

- **Нумерация рёбер меняется после каждого скругления.** Нельзя собрать
  список `Edge*` один раз и применять дальше по цепочке: индексы начинают
  указывать на другие рёбра. У меня так скруглились ребро на верхней грани
  седла и зуб на нижнем фланце. Искать кандидата надо заново в текущем
  `body.Tip`, помечая обработанные по координате середины ребра.
- **Подбирать рёбра до `recompute` бесполезно** — у только что созданной
  фичи `Shape` не посчитан, список рёбер пуст.
- **`f.State` и `Shape.isValid()` не ловят брак.** Скругление рапортует
  успех, проходит проверку и портит форму на следующем пересчёте;
  `Shape.check()` потом бросает `Unorientable shape`. Нужен финальный проход
  по готовому телу.
- **Дно гнезда гайки лежит в той же плоскости стыка.** Если не исключить
  его из отбора, галтель нарастит материал внутрь гнезда и гайка
  перестанет влезать.
- Каждая попытка — два пересчёта тела со 100 зубьями, то есть полная
  пересборка с перебором рёбер занимала **около 6 минут**.

Единственное, что реально убирало причину, — сдвинуть `NachRadius` до 18,
чтобы подошва седла целиком легла на спицу. Тогда диагонали исчезают и
стык скругляется штатно. Но это двигает хомут на 5 мм наружу.
